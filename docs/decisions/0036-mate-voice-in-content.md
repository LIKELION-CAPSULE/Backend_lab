# 0036 메이트 목소리는 메이트 데이터로, 샘플은 Aliving2D가 같은 값으로 만든다

- 결정
  - 메이트 목소리를 `characters.tts_voice` · `tts_model` · `tts_instructions`에 둔다. 대화 음성(api.md 28, ADR 0034)은 이 값으로 TTS를 부르고, 비어 있으면 운영 설정 `capsule.tts`의 기본값(`voice` · `model` · `instructions`)을 쓴다
  - '목소리 듣기' 샘플(`voice_sample_url`, api.md 31)은 모델 제작 도구 Aliving2D가 만든다. 목소리를 고르고 OpenAI TTS로 들어 본 뒤 정하면, 그 mp3를 버킷에 올리고 관리용 API(ADR 0033)로 목소리 · 모델 · 말투 지시 · 샘플 경로를 한 번에 등록한다
  - content가 계약 `VoiceQuery`(메이트 id → 목소리)를 내놓고 dialogue가 읽는다
- 이유
  - 샘플과 대화 목소리가 같은 모델 · 목소리 · 말투 지시로 만들어져야 '목소리 듣기'에서 들은 목소리로 대화한다. 같은 값을 한곳(메이트 행)에 두면 어긋나지 않는다
  - 목소리는 여러 개를 들어 보고 고르는 일이라, 고르는 도구(Aliving2D)에서 바로 들어 볼 수 있어야 한다. Aliving2D는 이미 OpenAI 키를 쓴다
  - 운영 설정(`capsule.tts.voices`, 메이트 id → 목소리)은 바꿀 때마다 배포 설정을 고쳐야 하고 샘플과 이어지지 않는다
- 버린 대안
  - 백엔드가 샘플을 만든다: 목소리를 등록하면 서버가 TTS로 샘플을 만들어 버킷에 둔다. 서버에 버킷 쓰기 키가 필요하고(ADR 0024는 읽기만), 고르기 전에 들어 보려면 미리듣기 API가 따로 필요하다
  - mp3를 사람이 직접 올린다: 실제 대화 목소리와 다를 수 있다
  - 운영 설정 `capsule.tts.voices` 유지: 위 이유
- 대가
  - Aliving2D와 서버가 같은 OpenAI 음성 API를 각자 부른다. 모델 이름 · 말투 지시를 행에 같이 저장해서 서버가 Aliving2D가 쓴 값 그대로 부르게 한다. 사용자 설정의 말 빠르기(29)는 서버가 말투 지시 뒤에 덧붙이므로 샘플은 '보통' 빠르기다
  - 메이트별로 어떤 목소리를 쓸지는 기획 판단(J-10)이라 칸만 만들고 값은 정해지면 넣는다
