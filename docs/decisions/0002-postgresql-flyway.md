# 0002 PostgreSQL + Flyway (타임스탬프 버전)

- 결정: DB는 PostgreSQL, 스키마 변경은 Flyway만. 버전은 `V<yyyyMMdd>_<HHmmss>__<모듈>_<설명>.sql`. ddl-auto는 validate.
- 이유: 유저-캐릭터-호감도는 관계형, 대화 로그는 JSONB로 유연하게. 타임스탬프 버전이라 둘이 동시에 만들어도 번호가 겹치지 않고, 파일명의 모듈로 소유자를 판정할 수 있음.
- out-of-order: 모든 환경(공용 application.yml)에서 켬. 타임스탬프 버전은 만든 순서와 머지 순서가 달라서, 끄면 늦게 머지된 '더 이른' 마이그레이션 때문에 배포 DB에서 validate가 실패함(빈 DB로 도는 CI는 못 잡음).
  - 대가: 환경마다 적용 순서가 다를 수 있음 → 마이그레이션끼리 의존하지 않아야 함. 각 모듈이 자기 테이블만 바꾸는 규칙(파일명 모듈, 남의 테이블은 확인 질문)이 이를 받침.
- 버린 대안: MySQL(JSONB 부재), JPA ddl-auto(변경 이력 공유 불가), 순번 버전(V5 충돌), out-of-order를 로컬에서만 켜고 rebase 때 파일명 다시 짓기(수작업이라 잊으면 배포 실패, 막으려면 CI 검사가 또 필요).
