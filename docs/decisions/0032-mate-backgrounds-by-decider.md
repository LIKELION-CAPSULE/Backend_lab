# 0032 배경은 메이트 기준 목록, 대화 흐름에 따라 결정 모델이 고른다

- 결정
  - 연결 화면 배경을 메이트마다 여러 장 둔다: `character_backgrounds`(content 모듈, `code` · `name` · `image_url` · `guide` · `is_default`). 이미지는 다른 에셋처럼 Supabase Storage 경로만 저장한다(ADR 0024)
  - 연결을 시작하면 기본 배경. 답장(20 · 28)이 끝나면 결정 모델(`Decider`)이 사용자 말 + 답장 + 지금 배경을 보고 "그대로(KEEP)" 또는 다른 배경 하나를 고른다. 보기 설명은 배경마다 `guide`. 표정 고르기(ADR 0028)와 같은 방식이고 같은 대기 한도(fact-pick-wait)를 따로 기다린다. LLM 답장일 때만 고른다(대체 대사 · 안전 경고 · 재전송은 그대로)
  - 지금 배경은 연결에 저장한다: `connections.background_code`(session 모듈, NULL이면 기본). dialogue는 session 계약 `ConnectionBackgrounds`로 읽고 바꾼다. 이어하기(17)는 마지막 배경으로 시작
  - 연결 시작 · 이어하기는 배경 목록 전체(`backgrounds`)와 지금 배경(`background`)을 주고, 답장은 바뀐 때만 `background`를 준다. 프론트는 목록을 미리 받아 둔다
- 이유
  - 스터디룸이 없어지면서 룸 기준 배경(`room_backgrounds`)도 지웠다. 배경은 "누구와 어디에 있나"라서 메이트에 붙는다
  - 장소가 바뀌는지는 문장 뜻을 봐야 한다(“카페 가자” vs “카페 싫어”). 키워드 규칙은 문맥을 못 본다(ADR 0028 · 말의 종류 판정과 같은 이유). 결정 모델은 보기 밖 값을 내지 않아 목록 밖 배경이 나오지 않는다
  - 배경 상태를 dialogue에만 두면 이어하기(session)가 dialogue를 불러야 해서 순환이 생긴다. 연결 행에 두면 session이 그대로 읽는다
- 버린 대안
  - 답장 LLM이 대사와 함께 배경 태그를 쓰기: 표정 태그에서 목록 밖 값 · 빠뜨림이 계속 났다(ADR 0028)
  - 사용자가 고르기: 요청은 "대화 흐름에 따라 자동"
  - 캐릭터 설정(profile.yml)에 배경 목록 두기: 이미지 경로는 다른 에셋처럼 content DB에 있어야 메이트 화면 · 연결 시작이 같은 곳을 본다
  - 시간대 · 상황 규칙으로 서버가 계산: 대화로 장소를 옮기는 장면을 못 만든다
- 대가
  - 답장마다 결정 호출이 하나 늘어난다(배경이 2장 이상인 메이트만). 표정을 고른 뒤 이어서 부르므로 20 응답 · 28 `done`이 약 0.2초(최대 fact-pick-wait 1.5초) 늦어진다. 첫 글자 속도는 그대로. 늦어짐이 문제면 표정 질문과 한 번의 결정 호출로 합칠 수 있다(`Decider`는 질문 여러 개를 한 번에 받음)
  - 결정 모델이 너무 자주 바꿀 수 있다. 몇 턴 안에는 다시 안 바꾸는 규칙 등은 확정 필요(판단 백로그 J-18)
  - 실제 배경 목록 · 이미지 · `guide` 문구는 에셋이 오면 마이그레이션으로 넣는다. 그 전에는 배경이 없는 메이트라 빈 목록
