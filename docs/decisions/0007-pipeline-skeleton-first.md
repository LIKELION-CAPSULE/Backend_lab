# 0007 개발 파이프라인: 명세 → 얇은 뼈대 → 도메인 분리

- 결정: 노션의 API 명세·DB를 spec-sync로 가져오면(0008) skeleton 스킬이 전체 플로우가 도는 얇은 뼈대를 만든다. 단순한 건 구현, 판단·LLM은 Fake + judgment-backlog. 이후 모듈 담당별로 나눠 개발한다.
- 이유: 공용 코드·계약·스키마를 갈라지기 전에 깔아야 이후 충돌이 적다. 전체 플로우가 처음부터 돌아야 바로 테스트하며 볼 수 있다. 판단 영역을 미리 구현하면 기획이 정해지기 전에 코드가 기획을 정해버린다.
- 버린 대안: 처음부터 도메인 분리(공용·계약 동시 작성으로 충돌), 뼈대에서 전부 구현(기획 결정이 코드에 숨음).
- 단계 전환: .harness/phase (skeleton → domain)를 harness PR로 바꾼다.
