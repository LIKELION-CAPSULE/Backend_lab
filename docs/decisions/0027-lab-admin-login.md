# 0027 실험실 관리자 로그인 (아이디 · 비밀번호, 서명한 토큰)

- 결정
  - 실험실(운영 설정 포함, ADR 0026)에 관리자 로그인을 둔다. 계정은 환경변수로만: `CAPSULE_ADMIN_USERS_<아이디>=<비밀번호>` (`capsule.admin.users`)
  - 비밀번호는 Spring 저장 형식: `{bcrypt}$2a$10$…`(권장) 또는 `{noop}평문`. 형식이 틀리면 앱이 시작하지 않는다
  - 로그인(`POST /internal/llm-lab/api/login`)하면 서명한 토큰을 준다: `아이디.만료.서명`(HMAC-SHA256, 키는 `capsule.auth.jwt-secret`). 화면은 그 토큰을 고정 토큰과 같은 `X-Lab-Token` 헤더로 보낸다. 서버에 세션 · 쿠키를 두지 않는다
  - 서명 안에 그 계정의 저장된 비밀번호 값을 넣는다: 비밀번호를 바꾸면 그 전 토큰은 바로 못 쓴다. 유지 시간은 `capsule.admin.session-ttl`(기본 12시간)
  - 관리자 계정이나 고정 토큰(`capsule.llm.lab.token`) 중 하나라도 있으면 이 컴퓨터(loopback)에서 온 요청도 헤더가 있어야 한다. 둘 다 없을 때(로컬 기본)만 지금처럼 이 컴퓨터에서만
  - 로그인 주소만 인증 없이 열려 있어서, 접속 주소마다 1분에 10번까지만 받는다(Redis `RateLimiter`). 틀렸을 때 아이디가 틀렸는지 비밀번호가 틀렸는지 알려 주지 않는다
  - 운영 설정을 저장하면 로그에 바꾼 사람(관리자 아이디)을 남긴다
  - 프록시 뒤에서 실험실을 켜려면 관리자 계정이나 고정 토큰이 있어야 한다(없으면 시작 실패, ADR 0026)
- 이유
  - 고정 토큰 하나를 나눠 쓰면 누가 바꿨는지 모르고, 한 사람을 빼려면 모두의 토큰을 바꿔야 한다. 사람마다 계정이 있으면 로그에 이름이 남고, 한 계정만 비밀번호를 바꿔 끊을 수 있다
  - 화면이 이미 `X-Lab-Token` 헤더로 부르고 있어서, 로그인 토큰을 같은 자리에 넣으면 화면 · 흐름 테스트 페이지(flow.html)가 그대로 돈다
  - 헤더로 보내니 쿠키 인증의 CSRF 대비(토큰 · SameSite)가 필요 없다
- 버린 대안
  - 서비스 회원(users)에 관리자 표시: user 모듈(성욱) 테이블과 로그인 흐름을 바꿔야 하고, 관리자와 서비스 회원이 섞인다. 카카오 회원은 비밀번호도 없다
  - Spring Security 폼 로그인 + 세션 쿠키: 실험실 체인을 상태 있는 세션으로 바꾸고 CSRF를 다시 켜야 한다. 서버가 하나라도 재시작하면 로그인이 풀린다
  - 사용자용 JWT(`JwtEncoder`)를 그대로 쓰기: 관리자 토큰이 `/api` 사용자 토큰으로도 통하게 될 수 있다. 모양이 다른 별도 토큰으로 막았다
  - 외부 로그인(SSO · OAuth): 2인 개발 · 시연 단계에 비해 크다. 오래 열어 둘 거면 그때
- 대가
  - 서버에 로그인 목록이 없어 로그아웃은 화면에서 토큰을 지우는 것뿐이다. 토큰이 새면 만료(12시간)까지 쓰인다. 바로 끊으려면 그 계정 비밀번호를 바꾼다
  - `capsule.auth.jwt-secret`을 바꾸면 모든 관리자 로그인이 풀린다(사용자 로그인과 같이)
  - bcrypt 값은 사람이 만들어 넣어야 한다(예: `htpasswd -bnBC 10 "" 비밀번호 | tr -d ':\n'`, 앞에 `{bcrypt}`를 붙임). `{noop}`은 Railway 변수가 새면 비밀번호도 샌다
