# 0017 공용 개발 DB는 Supabase 개발 프로젝트, 마이그레이션은 develop 머지 때만 (0016 일부 변경)

- 결정
  - 운영과 다른 Supabase 개발 프로젝트를 하나 만들고, `public` 스키마 하나를 둘(승희 · 성욱)과 프론트용 개발 서버가 같이 쓴다. Data API는 끈다(0016과 같은 이유)
  - 공용 개발 DB에 마이그레이션 · 예시 시드를 넣는 곳은 GitHub Actions `dev-db-migrate` 하나다. develop에 push되고 verify가 통과하면 Flyway CLI(앱과 같은 12.4, out-of-order)가 `db/migration` + `db/seed`를 넣는다
  - 앱이 공용 DB에 붙을 때는 `shared-db` 프로필(local 위에 얹음)로 Flyway를 끈다. `scripts/run-local.sh --shared`
  - 내 브랜치의 마이그레이션이 아직 머지 전이면 그 작업은 지금처럼 Docker 로컬 DB(`run-local.sh`, 옵션 없음)로 한다. 테이블 · 컬럼이 없으면 `ddl-auto: validate`가 시작할 때 알려주지만, 제약(CHECK) · 인덱스 · 데이터 변경은 못 잡고 실행 중 오류로 난다
  - 테스트 · CI는 Testcontainers 그대로(0003). Redis는 로컬 Docker 그대로(0009)
- 이유
  - 둘이 같은 데이터로 작업하고, 프론트도 같은 데이터를 본다(2026-11-04 합의)
  - 머지 전 마이그레이션이 공용 DB에 들어가면, 그 파일이 없는 상대 브랜치에서 Flyway 검증(`applied migration not resolved locally`)이 실패하고 상대 앱이 뜨지 않는다. 머지 전에 파일을 고쳐도 checksum이 어긋난다. 넣는 곳을 develop 하나로 두면 공용 DB는 항상 develop과 같다
  - 규칙을 사람 기억이 아니라 구조(프로필에서 Flyway 끔 + Actions만 마이그레이션)로 강제한다(0005)
- 버린 대안
  - 개발 프로젝트 안에서 사람마다 스키마 나누기(`currentSchema=dev_seonguk`): 마이그레이션 충돌은 없지만 "같은 데이터로 작업"이라는 목적과 맞지 않음
  - 로컬 앱이 공용 DB에 바로 마이그레이션: 단순하지만 위 충돌이 그대로 생김
  - 운영 프로젝트를 같이 쓰기: 개발 중 데이터와 예시 시드가 운영에 섞임
  - Docker 로컬 실행 없애기: 새 마이그레이션을 앱으로 돌려볼 곳이 없어짐
- 대가
  - 머지된 마이그레이션은 공용 DB에서 되돌릴 수 없다. 잘못 들어가면 새 마이그레이션으로 고친다(머지된 파일 수정 금지 규칙과 같음)
  - 둘이 같은 데이터를 바꾸므로 테스트 데이터가 서로 보인다. 지우거나 초기화할 때는 상대에게 먼저 말한다
  - 무료 플랜 pooler 연결 수를 셋이 나눠 써서 shared-db 풀은 2
  - 공용 DB와 각자 로컬 Redis가 따로라, 리프레시 토큰은 각자 로컬에만 있다(DB 데이터만 공유)
  - 예시 시드(R__)는 시드 파일이 바뀌는 머지마다 같은 id 행을 덮어쓴다. 시드 행은 공용 DB에서 손으로 고치지 않는다(바꾸려면 시드 파일 PR). 시드와 같은 unique 값(약관 code 등)으로 다른 행을 넣으면 워크플로가 실패한다
  - Fake 카카오 코드의 회원번호가 그대로 계정이 된다. 같은 번호를 쓰면 같은 계정을 같이 쓰게 되므로 대역을 나눈다: 승희 1xxx, 성욱 2xxx, 프론트 9xxx
  - 세션 자동 마감 배치(`@Scheduled`)가 각자 앱과 개발 서버에서 같은 DB를 대상으로 돈다. 행 잠금으로 다시 확인해서 두 번 마감되지는 않지만, 서버 1대 전제와는 다르다
  - develop 머지가 연달아 있으면 옛 커밋 기준 실행이 늦게 돌아 실패할 수 있다. 그때는 `dev-db-migrate`를 develop으로 다시 돌린다
  - Supabase PostgreSQL 메이저 버전(대시보드에서 확인)과 로컬 · 테스트(16)가 다를 수 있다. 문법 차이가 나면 둘 다에서 도는 SQL로 쓴다
- 남은 일
  - 프론트용 개발 서버를 어디에 띄울지. 띄우면 `local,shared-db` 프로필로 이 DB를 쓴다. 외부에 공개하면 Fake 카카오 때문에 아무 코드로나 로그인되므로, 그때 막을 방법을 정한다
