# 0026 운영 설정: 호감도 · 대화 · AI 설정을 배포 없이 바꾼다 (실험실 '운영 설정')

- 결정
  - `application.yml` 값을 기본값으로 두고, 실험실 '운영 설정' 화면에서 바꾼 칸만 DB에 저장해 그 위에 덮어쓴다(`common.settings.RuntimeSettings`)
  - 묶음 셋: `relation`(`capsule.relation.*` 호감도 숫자 · 단계), `dialogue`(`capsule.dialogue.*` 파이프라인 · 상태 반응 AI trigger · 점수표 · 기억 · 5초 기준 · 속도 제한), `llm`(`capsule.llm.*` 기본 · 대체 공급자, 용도별 등급과 한도, 등급 → 모델, 생각 설정, 가격)
  - 테이블은 모듈마다 자기 것: `relation_settings`(relation), `dialogue_settings`(dialogue). 다른 모듈 테이블을 읽지 않는다는 규칙을 지키려고. 모양은 같다(`section`, `overrides jsonb`, `updated_at`)
  - 바꿀 수 있는 칸은 허용 목록뿐. 열지 않는 칸: API 키 · 공급자 주소 · 버전 헤더(키가 다른 곳으로 새거나 호출이 다 깨짐), `log-content`(실제 사용자 대화 원문을 남길지는 개인정보 결정), 실험실 자체(`lab`), 시작할 때 한 번 읽는 값(HTTP 한도, 캐릭터 설정 캐시 시간 · 크기)
  - 칸은 점 경로(`anthropic.models`)이고 그 값을 통째로 바꾼다. 저장 전에 형식(레코드로 바뀌는지)과 범위(모듈별 check)를 보고, 틀리면 400 `INVALID_SETTING {path, reason}`으로 저장하지 않는다. yml 값도 같은 check를 거쳐 틀리면 앱이 시작하지 않는다
  - 읽기는 메모리 사본. 저장한 서버는 바로, 다른 서버는 30초 안에 다시 읽는다. DB를 못 읽거나(마이그레이션 전) 저장된 값이 안 맞으면(칸 형식이 바뀐 배포 뒤) 그 묶음은 yml 값으로 돌고 로그를 남긴다
  - API는 실험실 아래: `GET /internal/llm-lab/api/settings`, `PUT /internal/llm-lab/api/settings/{section}` (본문 = 덮어쓸 칸 전체, `{}`면 전부 yml 값). 보안도 실험실과 같다(`X-Lab-Token`)
  - 개발 서버는 Railway 변수 `CAPSULE_LLM_LAB_ENABLED=true` + `CAPSULE_LLM_LAB_TOKEN`으로 실험실을 켠다. 프록시 뒤에서 토큰 없이 켜면 시작에 실패한다(접속 주소를 꾸밀 수 있어서)
  - 프롬프트(`prompt_versions`)와 캐릭터 설정(`character_profiles` 등)은 원래 DB에 있고 실험실 '프롬프트' · '캐릭터 설정' 탭에서 바꾸면 바로 서비스에 들어간다. 운영 설정은 그 밖의 숫자 · 선택만 맡는다
- 이유
  - 호감도 숫자, 어떤 AI를 쓸지, 프롬프트를 시연 · PM 피드백 중에 자주 바꾼다(승희 2026-11-06). 지금은 yml을 고쳐 PR → 머지 → 배포까지 가야 해서 한 번에 수십 분이 든다
  - 크레딧이 떨어지거나 한 공급자가 느릴 때 공급자를 바로 바꿀 수 있어야 한다(기존 대체 공급자는 Railway 변수라 재배포가 필요했다)
  - 실험실에 이미 토큰 인증 · 프롬프트 · 캐릭터 설정 편집이 있어서 탭 하나와 API 둘만 더하면 된다
  - yml을 기본값으로 남기면 저장한 칸만 다르게 보이고(화면에 '바꿈'), 되돌리기는 칸을 지우는 것뿐이다
- 버린 대안
  - Spring Cloud `@RefreshScope` + DB 프로퍼티 소스: 의존성이 하나 늘고, 설정이 불변 레코드(생성자 바인딩)라 다시 묶이지 않는다
  - 설정을 DB로 옮기고 yml을 지우기: 로컬 · 테스트가 DB 행에 기대게 되고, 새 칸마다 마이그레이션이 든다
  - 공용 테이블 하나(common 소유): 테이블마다 담당 모듈이 있다는 구역 규칙(zones.conf)과 안 맞는다
  - 별도 관리자 앱 · 로그인: 2인 개발 · 시연 단계에 비해 크다. 토큰 하나로 막고, 오래 열어 둘 거면 SSO 뒤에 둔다(LabSecurityConfig의 ponytail)
  - 전부 여는 허용 목록 없는 덮어쓰기: `anthropic.baseUrl`을 바꾸면 API 키가 그 주소로 나간다
- 대가
  - 실제 동작이 yml과 다를 수 있다. 화면 · 로그(`운영 설정 … 저장`)로만 보인다. 배포로 yml 기본값을 바꿔도 같은 칸을 덮어쓴 값이 있으면 그 값이 이긴다
  - 실험실 토큰 하나가 서비스 동작을 바꾸는 권한이 됐다. 토큰을 아는 사람은 호감도 규칙 · 공급자를 바꿀 수 있다
  - 한 요청 안에서 설정을 여러 번 읽으므로 저장하는 순간 걸친 요청은 앞뒤 값을 섞어 쓸 수 있다(그 한 번만)
  - 관계 단계 수를 바꾸면 캐릭터 설정의 단계별 말투(stageTones · samples)와 안 맞을 수 있다. 단계 번호는 저장하지 않아 다음 조회부터 새 구간으로 계산된다
